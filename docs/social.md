# مساحة الأعضاء — الإصدار 3.0.0

ثلاث صفحات مستقلة، بتصميم RTL أصلي وألوان شخصية، قائمة جانبية للحاسوب وتنقّل سفلي للهاتف. لا قوالب خارجية، لا حسابات/رسائل تجريبية في الموقع، ولا اعتماديات JavaScript إنتاجية جديدة.

| الصفحة | ما تعمل به فعليًا |
|---|---|
| `profile.html` | ملفك، تعديل التفاصيل والخصوصية والذائقة والمظهر والصورة |
| `profile.html?u=UUID` | ملف عضو آخر وصداقة/مراسلة/حظر، دون بريده أو إعداداته الخاصة |
| `friends.html` | بحث بالاسم/المعرّف، فلتر الذائقة، ترتيب بالاهتمامات المشتركة |
| `friends.html?tab=incoming` | الطلبات الواردة؛ توجد أيضًا `friends` و`outgoing` و`blocked` |
| `messages.html` | محادثات خاصة بين أصدقاء مقبولين، منفصلة تمامًا عن دردشة الغرف |
| `messages.html?with=UUID` | فتح/استعادة محادثة مع صديق بعد فحص الخادم |

روابطها متاحة من الرئيسية، ورابط الملف موجود أيضًا في قائمة حساب الغرفة ويفتح في تبويب آخر كي لا يقطع المشاهدة. الضيف يرى دعوة دخول واضحة، لا بيانات أعضاء أو نتائج مصطنعة.

## التفعيل — مطلوب مرة واحدة على Supabase

**هذا تغيير برمجي محلي، وليس ترقية نُفّذت على مشروع Supabase المنشور.**

1. احتفظ بنسخة احتياطية وفق سياستك المعتادة. في المشروع الذي يستخدمه `assets/js/config.js`، تأكد أن مخطط الغرف **01** (أو **02** المكافئ) موجود، وأن Supabase Auth يعمل. لا تغيّر مشروعًا قائمًا لمجرد إضافة هذه الصفحات.
2. افتح **Supabase Dashboard → SQL Editor → New query**، ثم نفّذ **كامل** `docs/sql/07-social.sql`. هو إضافة قابلة للتكرار؛ لا يحذف الغرف أو رسائل الغرف أو الملفات الاجتماعية القائمة. لا تنفّذ **00** لهذه الترقية.
3. ينشئ الملف جداول `wt_*` الاجتماعية، مخطط `wt_social_private`، الدوال، سياسات الصلاحيات، ووعاء Storage باسم **`wt-avatars`**. لا يلزم إنشاء الوعاء يدويًا. يلزم التنفيذ بحساب إدارة المشروع، لا من متصفح المستخدم أو بمفتاح `anon`.
4. ارفع الصفحات الست و`assets/` معًا بمراجع `?v=3.0.0`. لا ترفع `node_modules` أو اعتماديات الاختبار. جدّد الصفحات القديمة لدى المستخدمين.
5. سجّل الدخول بحسابين حقيقيين، وفعّل «الظهور في البحث» للحساب المراد العثور عليه؛ أرسل طلبًا من الآخر، اقبله، ثم افتح المراسلة. جرّب رفع صورة وحذفها، وإيقاف إيصالات القراءة والحظر أيضًا.

لطباعة ملف التفعيل من الطرفية، **دون تنفيذ أي شيء عن بُعد**:

```bash
node tools/sbctl.mjs sql --social
```

إن لم يُنفَّذ 07 تعرض الصفحة مسار الملف وزر إعادة محاولة، ولا تدّعي حفظًا محليًا بديلاً. الغرف المحلية أو Java تبقى مستقلة؛ **ملفات الأعضاء والصداقة والمراسلة الخاصة تعتمد على Supabase Auth/REST/Storage**، ولا توجد محاكاة خلفية اجتماعية ضمن الموقع. `sbctl doctor` وملف 05 يفحصان مخطط الغرف القديم، وليس بديلًا لفحص الصفحات الاجتماعية.

> **تنبيه 00:** ملف إعادة الضبط القديم يحذف دوال `wt_*`، ومن ضمنها الدوال الاجتماعية، حتى لو لم يحذف جداولها الجديدة. لا تستعمله للترقية أو إصلاح الصور؛ إن استُعمل عمدًا يلزم إعادة 01 ثم 07. لا تُعد ملفات إعادة الضبط ضمانًا لحذف الصور من Storage.

## الملف الشخصي

- اسم عرض (2–24)، معرّف فريد (3–24: `a-z` وأرقام و`_`)، نبذة 280 حرفًا، موقع اختياري 60، رابط HTTP(S) حتى 200 دون بيانات دخول، تاريخ إنشاء الحساب المتاح، وصورة.
- حتى **8 من 12 اهتمامًا** و**3 عناوين مفضلة**؛ الأسماء من كتابة صاحب الملف وليست سجلات أفلام مزعومة.
- **بصمة المشاهدة**: كل نقطة تمثل اهتمامًا مختارًا بالفعل. تُعرض الاهتمامات المشتركة الحقيقية بدل نسبة توافق مختلقة.
- **مزاج المشاهدة**: على مهل / مستعد لسهرة / هادئ / مشغول. اختيار يدوي، **ليس حالة اتصال**.
- أربعة ألوان (نعناعي، بنفسجي، كهرماني، وردي) وثلاثة أغلفة هندسية مولّدة بـCSS محليًا (مدار، منشور، تموّج)، بلا تحميل صور أغلفة خارجية.
- مؤشر تفاصيل اختياري، معاينة للزائر، ومشاركة رابط الملف فقط — دون بريد أو رموز جلسة.
- تبويبات تحرير يمكن تنقّلها بالأسهم وHome/End، حالة تعديلات غير محفوظة، تأكيد التراجع، وإبقاء الحقول عند الخطأ. الحفظ لا يستبدل بيانات Token.
- الاسم والصورة والمعرّف يُزامنون مع بيانات حساب Auth لظهور الصورة عند دخول جديد أيضًا. تعديل اسم الحساب من واجهة الغرفة يُحدّث اسم الملف بواسطة Trigger.

### الخصوصية الافتراضية

- **الظهور في البحث متوقف** للحسابات الجديدة والموجودة عند الترقية؛ لا تُنقل عناوين البريد/أرقام الهاتف إلى الملفات.
- يمكن تعطيل استقبال الطلبات أو إيصالات القراءة، وإظهار عدد الأصدقاء اختياري. لا توجد API لعرض شبكة صداقات عضو آخر.
- عدم الظهور في البحث **ليس ملفًا سريًا كاملاً**: أعضاء مسجلون يعرفون رابطه يستطيعون رؤية تفاصيله المضافة، ما لم يوجد حظر بين الطرفين. هذا موضّح في المحرّر.
- بريد الحساب يظهر لصاحبه فقط من جلسة Auth؛ ليس من نتائج البحث أو بيانات الطرف الآخر.

## صورة من الهاتف

1. اختيار من معرض الهاتف/ملفات الجهاز (`image/*`، دون إجبار المستخدم على فتح الكاميرا).
2. فحص التوقيع الفعلي: JPEG/PNG/WebP، وHEIF/HEIC/AVIF عند قدرة المتصفح على فكّها. حد إدخال 20 MiB و50 ميغابكسل. SVG والملفات الأخرى مرفوضة. عند عدم دعم HEIC تُعرض رسالة لتحويلها إلى JPEG، لا نجاح صوري.
3. قصّ وتكبير وتدوير 90°، وسحب بالفأرة **أو اللمس**. الأسهم تحرّك الإطار وShift للتحريك الدقيق؛ منزلق التكبير ذو تسمية وصول.
4. إعادة رسم **512×512** وتصدير WebP حتى **256 KiB**؛ لا تُرفع البايتات الأصلية أو اسم الملف الأصلي أو EXIF/GPS.
5. رفع إلى `UUID/48-hex.webp` عشوائي جديد، دون overwrite، ثم حفظ المرجع في الملف، ثم محاولة تنظيف الصورة القديمة. فشل الحفظ يبقي الصورة السابقة ويحاول إزالة الملف الجديد. التنظيف بعد فقد الاتصال أفضل جهد وقد يحتاج إدارة الأجسام غير المرتبطة على الخادم عند حالات انقطاع نادرة.

**الوعاء علني للصور فقط.** رابط الصورة قد يفتحه من يعرفه خارج التطبيق؛ تُذكر هذه الحقيقة قبل الحفظ. لا ترفع وثائق حساسة. حذف المرجع/الأصل لا يسترجع نسخًا احتفظ بها الآخرون أو يضمن تفريغ كل CDN/browser cache فورًا؛ مدة الكاش المطلوبة ساعة.

Storage يحمي نطاق الوعاء بسياسات Restrictive إضافية حتى بوجود سياسة قديمة واسعة من تطبيق آخر، دون تغيير سلوك الأوعية الأخرى. يسمح بإضافة/حذف ملفات مجلد صاحب JWT فقط، لا تعديل صورة عضو آخر ولا استبدال ملف قائم. سياسة الحذف تمنع حذف الصورة المشار إليها حاليًا في الملف، حتى من عملية تنظيف متأخرة. API حفظ الملف ترفض الصور غير الموجودة أو المسارات الخارجية/التابعة لغير صاحبه. تُعرض الأحرف الأولى إذا تعذّر تحميل الصورة.

## الصداقة والمراسلة

- طلب/قبول/رفض/إلغاء/إزالة/حظر/إلغاء حظر عبر الخادم، لا مجرد تبديل أزرار. صاحب الطلب لا يقبل طلبه بنفسه. تعطيل الطلبات يمنع الجديد فقط.
- الحظر يحذف علاقة الصداقة/الطلب ويمنع البحث وقراءة الملف الجديد والإرسال؛ لا يعيد إلغاء الحظر الصداقة تلقائيًا.
- المراسلة بين **صديقين مقبولين دون حظر**. إنشاء المحادثة فريد للزوج؛ تاريخها السابق متاح لطرفيها للقراءة بعد الإزالة/الحظر، دون إرسال جديد. بيانات الطرف المحظور وإشارات كتابته/قراءته الجديدة محجوبة.
- نص حتى 2000، إيموجي، رد مع اقتباس وانتقال للأصل، تعديل نصك وحذف رسالتك للجميع. بعد الحظر يمكن حذف نصك القديم، لا تعديله أو مراسلة الطرف الآخر. الحذف يمحو النص وبيانات دعوة الغرفة، ويُحدث الاقتباسات ولا يحتفظ بنسخة نص مخفية فيها.
- صفحات تاريخ من 50، وتحديثات تغيرات من 100. تسلسل `version` أحادي التزايد تحت قفل الزوج يعالج الإضافة **والتعديل والحذف** حتى للرسائل القديمة، دون الاعتماد على ساعات العميل أو «معرّف آخر رسالة» وحده. لا تُقدَّم رسائل تاريخ قديمة كأنها رسائل واردة جديدة.
- فحص تغييرات كل نحو 4 ثوانٍ بعد انتهاء الطلب السابق؛ قائمة المحادثات نحو 12 ثانية أو أكثر. تتوقف المتابعة أثناء إخفاء الصفحة، وتُلغى قراءات المحادثة السابقة عند التبديل. المهلة تشمل قراءة استجابة الخادم (8.5 ثوانٍ بعد فحص جلسة Auth ذي مهلته المستقلة).
- لا تُعلَّم الرسائل مقروءة إلا عند فتح المحادثة وظهور الصفحة والاقتراب من أسفلها، وليس أثناء قراءة الأقدم أو عرض قائمة المحادثات على الهاتف. إيقاف الإيصالات يمنع الطرف الآخر من قراءتها، دون تعطيل عدّادك الخاص.
- «يكتب الآن» حقيقي، ناتج عن الإدخال وينتهي بعد 6 ثوانٍ. علامة واحدة تعني الحفظ على الخادم، لا دليل تسليم/اتصال؛ علامتان عند إيصال قراءة مسموح فقط.
- مسودات وتعديلات محلية **منفصلة لكل حساب ومحادثة**؛ الإرسال غير المؤكد يحتفظ بـnonce عشوائي لإعادة آمنة دون تكرار. المسودات المعلّقة منفصلة لكل nonce، وتُزال عند وصول تأكيد أو ظهور الرسالة في التحديث. الخروج يحذف مسودات الحساب من الجهاز.
- لا تخزين موثوقًا عند منع localStorage؛ تبقى الكتابة في ذاكرة الصفحة ويظهر تنبيه بعدم إغلاقها. المسودات المحلية ليست تشفيرًا، ولا بديلًا للنسخ الاحتياطي أو إيصال الخادم.
- Enter يرسل على لوحة مفاتيح الحاسوب، وShift+Enter لسطر. على جهاز لمس Enter لسطر وزر الإرسال للتأكيد. تستخدم الواجهة VisualViewport عند تداخل لوحة مفاتيح الهاتف.
- **بطاقة دعوة لغرفة**: تختار من آخر 30 غرفة Supabase؛ يعيد الخادم فحص وجود الكود ويأخذ العنوان منه، دون الثقة بعنوان العميل أو تضمين مفتاح منشئ. كلمات مرور الغرف تبقى مطلوبة. لا تُدّعى صلاحية غرفة محلية/Java لا يستطيع هذا الخادم التحقق منها.

## حدود الأمان والتشغيل

- كل الجداول الاجتماعية عليها RLS، وقراءة/كتابة العميل المباشرة وتسلسلات الرسائل ممنوعة. السطح المسموح RPCs ذات أسماء محددة، `SECURITY DEFINER` و`search_path` ثابت، وهوية الفاعل من `auth.uid()` فقط. المخطط الخاص غير قابل للوصول للعميل.
- دوال المستخدمين لـ`authenticated` فقط، لا `anon`. لا `service_role` في المتصفح. الدوال تعيد حقول JSON صريحة، لا بريدًا أو مفاتيح أو أدوار تحكم بغرف.
- قيود أطوال/أنواع/اهتمامات، منع العبث بمسار الصورة/المرسل/هوية صاحب الملف، وردود من محادثة أخرى، وتحديد معدل للرسائل والطلبات والتعديلات والكتابة وتحرير الملف.
- النصوص لا تُنفَّذ كـHTML؛ الروابط الخارجية HTTP(S) فقط مع `noopener noreferrer`، وأفاتارات Storage محدّدة المسار، لا URLs عشوائية من metadata.
- **المحادثات ليست مشفّرة من طرف إلى طرف.** الخادم/مسؤول قاعدة البيانات يستطيع الوصول إليها؛ سياسات التطبيق تقصر عرضها على طرفي المحادثة. موضّح في شاشة الدردشة.
- لا بحث غير مسجل، ولا نتائج/حضور/ساعات مشاهدة أو إشعارات متخيلة. تعذّر الخادم يعرض خطأ وإعادة محاولة، ولا يتحول إلى قاعدة محلية بمظهر نجاح حقيقي.

## اختبارات قابلة للإعادة

```bash
npm test                         # 13 مجموعات بلا اعتماديات؛ تشمل عقد العميل الاجتماعي
npm ci                           # اعتماديات تطوير فقط
npm run test:social:db            # PostgreSQL فعلي مضمّن عبر PGlite
npx playwright install chromium
npm run test:social:browser       # Chromium + SQL 01 و07 فعليان خلف بوابة HTTP اختبارية
npm run test:browser              # تراجع الغرف/الفيديو/الحضور والدردشة الحالية
```

اختبارات SQL تستخدم أدوار Auth وStorage وpublication تجريبية، ثم **ملف 01 الحقيقي** و**ملف 07 الحقيقي**؛ لا تعيد اختراع مخطط الغرف. تفحص الخصوصية والصداقات وصلاحيات الجداول والتسلسلات، صور المجلد الخاص وrollback، الإرسال المعاد، المؤشرات وصفحات تغيرات تتجاوز 100 رسالة، الحذف والقراءة/إخفاء نشاطها والحظر، ومنع الرد من محادثة أخرى وإعادة تنفيذ الترقية دون فقد بيانات.

المتصفح يختبر نموذج الملف، الصورة وقصّها وتكبيرها وتدويرها و**إيماءة لمس فعلية**، البحث وسباق استجاباته والتحميل المتدرج، قبول طلب بين حسابين، الدردشة والرد والتعديل والحذف وXSS كنص، دعوة غرفة، فقد تأكيد الإرسال، الانقطاع/إعادة الفتح واستعادة المسودة، سياسة القراءة في السجل/الصفحة المخفية، الحظر، الخروج، والقياسات 320–1440. إشارة إخفاء الصفحة مضبوطة داخل الاختبار، وليست ادعاءً باتصال متصفح مستخدم فعلي.

**حد التحقق:** بوابات HTTP وGoTrue وتخزين بايتات الصور معزولة للاختبار؛ لا تُنشأ حسابات حقيقية أو يُرسل SQL إلى مشروع Supabase المنشور. لا تُقدَّم تلك البوابة أو بياناتها عبر معاينة الموقع. التحقق المحلي لا يغني عن فحص إعدادات المشروع/Storage وAuth على الاستضافة بعد تنفيذ الترقية.
