# 🍿 WatchTogether — شاهدوا معاً

موقع **مشاهدة جماعية متزامنة** بواجهة عربية احترافية (HTML/CSS/JS) مع **سيرفر Java** اختياري.

- **الصفحة الرئيسية** (`index.html`): منطقة إضافة رابط المشاهدة + إنشاء غرفة + الدخول بكود.
- **صفحة الدخول** (`auth.html`): إنشاء حساب / تسجيل دخول / دخول كضيف.
- **صفحة الغرفة** (`room.html`): المشغّل في الأعلى وشريط تحكمه **أسفله مباشرة** (زر تشغيل · الوقت · شريط تقدم · كتم صوت — بلا شريط صوت وبلا ملء شاشة وبلا أزرار تقديم/ترجيع)، ثم أزرار المقاطع والرسائل والقائمة، و**الرسائل ظاهرة دائماً وتأخذ المساحة الكبيرة**، مع قائمة جانبية تجمع المشاركين والمنظّمين والأدوات.

### 🎛️ شريط التحكم في الغرفة (2.6)

| العنصر | الحالة |
|--------|--------|
| شريط التقدم + زر التشغيل | ✅ أسفل الفيديو داخل بطاقة المشغّل (خارج الصورة) |
| كتم الصوت (زر) | ✅ موجود |
| شريط الصوت (المنزلق) | ❌ محذوف نهائياً |
| ملء الشاشة | ❌ محذوف نهائياً (بلا زر وبلا اختصار `F`) |
| أزرار التقديم/الترجيع (±10ث) | ❌ محذوفة نهائياً (يبقى مفتاحا السهمين للتنقّل السريع) |
| إخفاء التحكم التلقائي | ❌ أُلغي — الشريط خارج الصورة وظاهر دائماً |
| بطاقة المشغّل | ✅ عرض محدود (`min(100%, max(320px, 54vh))`) لتبقى الرسائل هي المساحة الكبرى |

> 📱 **متجاوب بالكامل**: يعمل على iPhone و Android والحاسوب، مع مراعاة المساحات الآمنة وحجم اللمس، وشريط تحكم وأدوات يعاد ترتيبها على الشاشات الصغيرة.

## 🚀 التشغيل السريع

### الطريقة 1 — سيرفر Java (صفحات + مزامنة في خادم واحد)

```bash
cd watch_together/java-server
./build.sh && ./run.sh          # ويندوز: build.bat ثم run.bat
```
→ **http://localhost:8080** (الخادم يطبع أيضاً IP الشبكة المحلية لمشاركته مع صديقك)

تغيير المنفذ: `PORT=3000 java -cp out com.watchtogether.Main`

### الطريقة 2 — استضافة عادية (cPanel / Netlify / GitHub Pages)

1. ارفع **محتويات** `watch_together/` إلى `public_html`.
2. نفّذ [`docs/schema.sql`](docs/schema.sql) في Supabase → **SQL Editor → Run**.
3. لتفعيل صفحة الدخول: **Dashboard → Authentication → Providers → Email → Enable**
   (وللتجربة بدون تأكيد بريدي: أطفئ **Confirm email**).
4. افتح الموقع → الشارة يجب أن تقول **«Supabase متصل»**.

### الطريقة 3 — تجربة محلية بلا سيرفر

```bash
cd watch_together && python3 -m http.server 8080
```
يعمل في **الوضع المحلي** (مزامنة بين تبويبات نفس الجهاز) — ممتاز لتجربة التصميم.
للدخول المباشر في الوضع المحلي أضف `?local=1` للرابط.

## 🔐 صلاحيات الغرفة والمزامنة (2.4.0)

- لا تمنح قيمة `host=1` في الرابط صلاحيات بحد ذاتها؛ تُثبت هوية المنشئ بمفتاح عشوائي خاص محفوظ على جهازه ولا يُضاف إلى رابط الدعوة.
- تحفظ Supabase أسرار المنشئ والأعضاء في مخطط `wt_private` غير المكشوف عبر PostgREST، وتتحقق دوال RPC من الدور قبل قبول حالة المشغّل أو تعديل الأدوار والقائمة.
- في سيرفر Java تُحفظ بصمات مفاتيح التحكم فقط، ويصدر الخادم رقم الحالة التسلسلي.
- ينضم الضيف كمشاهد، ويستطيع إضافة مقاطع للقائمة؛ لا يبدأها للجميع إلا المنشئ أو المنظّم. المزامنة تعيد الاتصال وتستطلع قاعدة البيانات تلقائياً عند انقطاع Realtime.
- عند انتهاء الجلسة تُحفظ الحالة عبر المسار نفسه الذي يتحقق من الصلاحية، بما في ذلك RPC مع `keepalive` في Supabase.

## 💬 «تعذّر إرسال الرسالة» — إصلاح جدول الرسائل (التحديث 2.5.0)

إن ظهر لك (في Console أو في تقرير التشخيص):

```
supabase: Could not find the 'body' column of 'messages' in the schema cache
```

فالسبب أن جدول `messages` في مشروعك **قديم**: عمود نصّ الرسالة فيه اسمه
`text`/`message`/`content` بدل `body`، أو ينقصه أحد الأعمدة الجديدة؛ ولأن
`bootstrap.sql` يستعمل `create table if not exists` فهو لا يعدّل الجدول القائم.

**ما فُعل لمنع تكرار المشكلة:**

1. **إصلاح في القاعدة**: [`docs/repair-messages.sql`](docs/repair-messages.sql) — يعيد تسمية العمود
   القديم إلى `body` (أو يضيفه)، ويثبّت الشكل، والصلاحيات، وRealtime، ثم
   ينفّذ `notify pgrst, 'reload schema';`. والقسم نفسه أُضيف داخل `bootstrap.sql`
   و`schema.sql` و`migration.sql` فلا تعود المشكلة في أي مشروع جديد.
2. **تكيّف تلقائي في المتصفح**: عند الخطأ يكتشف العميل العمود الفعلي من OpenAPI
   أو من صفّ حقيقي، ويكتب فيه ويقرأ منه، ويتجاهل أي عمود يرفضه الجدول القديم —
   فتعمل الدردشة فوراً، ويظهر تنبيه واحد بالعربية يشرح السبب والحل.
3. **تشخيص صريح**: نافذة «تشخيص الاتصال» و`node tools/sbctl.mjs doctor` صارا
   يفحصان عمود النصّ (`body`) ويقولان بصراحة إن كان الجدول قديماً.

> 🧰 أوامر سريعة: `node tools/sbctl.mjs doctor` للفحص · `node tools/sbctl.mjs sql --repair`
> لطبع ملف الإصلاح · `node tools/sbctl.mjs smoke` لاختبار حي للدردشة والمزامنة.

## 🛠️ سيرفر Supabase وتشخيص الاتصال (التحديث 2.3.0)

> **«في الغرفة يتعذّر الاتصال»** — هذا الجزء يحلّه ويمنع تكراره.

### المشكلة التي كانت تُرعب المستخدم

كان الاتصال يفشل بلا سبب واضح: «تعذّر الاتصال بالغرفة» فقط، دون أن يعرف المستخدم
هل السبب هو الجداول، أو المفتاح، أو RLS، أو مشروع موقوف، أو حجب للشبكة.
وأخطر من ذلك: **جدول واحد ناقص (مثل `messages`) كان يُسقط الاتصال كله**، مع أن
مزامنة الفيديو كان يمكن أن تعمل.

### الحل في 3 أجزاء

**1) نافذة «تشخيص» داخل الغرفة** — زر في الشريط العلوي يفحص المشروع من متصفحك:
هل REST يستجيب؟ هل الجداول موجودة؟ هل Realtime يعمل؟ وما **السبب + الحل**؟
مع زر «إعادة الاتصال» وزر «نسخ التقرير».

**2) التطبيق صار متسامحاً** — غياب جدول `messages` لم يعد يُسقط الاتصال:
المزامنة تعمل، والدردشة فقط تتعطّل مع تنبيه واضح. وكل خطأ يُترجم
إلى سبب وحل بالعربية (42P01 → نفّذ المخطط، 401 → المفتاح، 42501 → RLS، …).

**3) أداة `sbctl` — إنشاء سيرفر جديد بأمر واحد:**

```bash
cd watch_together

# فحص المشروع الحالي (REST + الجداول + Realtime + كتابة/قراءة)
node tools/sbctl.mjs doctor

# إنشاء مشروع Supabase جديد + تنفيذ المخطط + ربطه بالموقع تلقائياً
export SUPABASE_ACCESS_TOKEN="sbp_..."     # من supabase.com → Access Tokens
node tools/sbctl.mjs create --name wt-new \
  --org-id <ORGANIZATION_ID> --db-password "<كلمة مرور قوية>"

# تبديل المشروع يدوياً (يرفع أيضاً رقم الكاش ?v=)
node tools/sbctl.mjs set --url "https://xxx.supabase.co" --key "eyJhbGci..."

# اختبار حي: ينشئ غرفة، يكتب حالة، يقرأها، يحذفها
node tools/sbctl.mjs smoke
```

الدليل الكامل: [`docs/new-supabase-server.md`](docs/new-supabase-server.md).

## ⚡ نموذج المزامنة (بالتفصيل)

```
المنشئ/المنظّم يغيّر الحالة ──► تحقق وترقيم خادمي ──► كل المشاركين يصحّحون عبر Realtime أو الاستطلاع
              │
              └─► كل 5 ثوانٍ  ──► رفع الحالة إلى قاعدة بيانات الغرفة (rooms.state)
              └─► عند الخروج  ──► رفع فوري (آخر مستخدم = حفظ وقت الغرفة)

من يدخل متأخراً ──► يقرأ rooms.state ──► يحسب:  pos + (الآن − t)  إذا كان playing
                 ──► يقفز إلى الوقت الحالي مباشرة (يلتحق بالجميع)

الترتيب بين المشاركين ──► ساعة منطقية (rev) + كسر تعادل بمعرّف العميل
                      ──► يستحيل أن يتجاهل اثنان تحديثَي بعضهما للأبد
Supabase ──► بثّ Realtime + **استطلاع احتياطي كل 2.5 ثانية** (يعمل حتى لو تعطّل Realtime)
```

> 🔗 **رابط الدعوة يحمل الكود + رابط الفيديو** (`room.html?id=CODE&v=…`)،
> فيلتحق الصديق بنفس المشاهدة حتى لو تأخّرت حالة الغرفة. استخدم زر **«نسخ الرابط»** أو **QR**.
>
> ⚠️ **الوضع المحلي** (= لا سيرفر) يعني أن كل جهاز له غرفة مستقلة —
> ستظهر رسالة صريحة في الغرفة تنبّهك أن أصدقاءك لن يلتحقوا بك.

**حقول الحالة** (`rooms.state`):

```json
{
  "url": "https://youtu.be/...",
  "kind": "youtube",
  "playing": true,
  "pos": 184.3,
  "t": 1700000000000,
  "rev": 42,
  "updatedBy": "c-XXXX",
  "updatedByName": "كريم"
}
```

| الحقل | الوظيفة |
|-------|---------|
| `t` | ختم زمني لآخر تحديث → أساس حساب الالتحاق للمتأخرين |
| `rev` | رقم تسلسلي → أي تحديث `rev` أقل أو يساوي المعروف **يُتجاهل** (لا ارتداد للخلف) |
| `updatedBy` | من تحكّم آخر مرة (يظهر في «آخر تحكّم») |

**تصحيح الانحراف** (يعمل كل ثانيتين وأيضاً عند وصول كل حالة):

| الفرق | الإجراء |
|-------|---------|
| ≤ 0.35 ث | لا شيء (متزامن) |
| 0.35 – 0.8 ث | تصحيح ناعم بسرعة 1.08× / 0.93× |
| 0.8 – 2.5 ث | تصحيح بسرعة 1.35× / 0.75× لمدة 1.5 ث |
| > 2.5 ث | قفزة فورية إلى الوقت الصحيح + تنبيه «تمت المزامنة» |

## 🔐 صفحة الدخول (`auth.html`)

- **إنشاء حساب**: اسم ظاهر + بريد + كلمة مرور (مع مؤشر قوة كلمة المرور).
- **تسجيل الدخول**: بريد + كلمة مرور، مع تجديد تلقائي للجلسة.
- **دخول كضيف**: اسم فقط — يعمل حتى بدون Supabase.
- الاسم يُحفظ في `user_metadata.full_name` ويظهر في قائمة المنضمين والرسائل.
- من داخل الغرفة: اضغط اسمك في الشريط السفلي لتغيير الاسم أو تسجيل الخروج.

لجعل الدخول **إلزامياً** قبل إنشاء غرفة:
```js
// assets/js/config.js
auth: { required: true, allowGuest: false }
```

## 🛡️ ملاحظات أمنية

- مفتاح `anon` في `config.js` عام بطبيعته؛ لا تضع `service_role` في ملفات المتصفح.
- `rooms` للقراءة فقط من العميل؛ تغيير الحالة يمر عبر `wt_apply_room_state`، وإدارة الأدوار والقائمة عبر RPC تتحقق من المفتاح والدور. أسرار المنشئ والأعضاء في `wt_private`، ولا يُرسل مفتاح المنشئ في رابط الدعوة.
- مفاتيح المنشئ والأعضاء محفوظة محلياً في المتصفح؛ فقدان بيانات المتصفح يفقد استعادة دور المالك. كود الغرفة ورابط الدعوة يمنحان الدخول كمشاهد فقط.
- الرسائل والحضور متاحان للقراءة/الإضافة وفق سياسات anon لتناسب الضيوف؛ لا ترسل فيهما بيانات حساسة.
- سيرفر Java: يرفض مسارات `../`، يحدّ رسالة WebSocket بـ 512KB، ويحفظ بصمات مفاتيح التحكم لا المفاتيح نفسها في `data/rooms.json` (مستثنى من Git).
- لا تُخزَّن كلمات مرور في الموقع — المصادقة كلها عبر Supabase Auth.
